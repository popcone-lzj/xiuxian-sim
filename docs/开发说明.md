# 《修仙家族模拟器》网页 Demo 开发说明

> 本文档交给开发方（Codex）独立完成一个**可玩的网页 Demo**。Demo 的目的是验证核心玩法好不好玩，画面以**文字 + 简单地图**为主，重点放在"选择 → 事件 → 因果 → 家族传承 → 扩张"这套循环上。
> 验收按配套文档《验收规则.md》执行。

---

## 1. 游戏概述与玩家定位

- **类型**：修仙题材的家族/势力模拟 + 策略扩张。
- **玩家身份：天道。** 玩家不直接操控角色的每个动作，角色有自己的性格和想法，会**自主行动**；玩家通过以下方式参与：
  1. 给角色选定**性格**和**培养方向**；
  2. 在事件弹出时做**抉择**；
  3. 每年/每阶段定**家族发展方向**（产业项目、扩张、外交、宣战等）；
  4. 在战斗中**指挥分队**、操作主将放技能；
  5. 使用**天道道具**进行干预（Demo 只做占位）。
- **核心体验**：玩家要感觉"我的选择真的改变了这个家族"——每个选择都有立刻看得见的结果，也会埋下几年甚至几代后才爆发的因果。
- **流程**：主角在大陆一角建立据点 → 修炼、经营、扩张 → 与世仇、魔修、其他宗门家族交锋或结盟 → **占领全部地块即通关**。
- **注意：本游戏没有"飞升"结局，不要实现任何飞升相关内容。**

---

## 2. 技术要求

| 项目 | 要求 |
|---|---|
| 形态 | 纯前端网页应用，**无后端** |
| 推荐技术栈 | Vite + TypeScript（UI 可用 React/Vue/原生，任选其一，保持简单） |
| 运行方式 | `npm install && npm run dev` 即可在本地浏览器游玩；`npm run build` 能成功构建 |
| 存档 | 使用 `localStorage`，支持**手动存档、读档**，至少 1 个自动存档位；存档包含完整世界状态 |
| 随机数 | 使用**可设定种子**的随机数生成器（方便复现 bug 和验收） |
| 数据驱动 | 事件、性格、产业、境界、功法/技能、地块类型、资源、天道道具等**全部放在独立 JSON 数据文件**（如 `src/data/*.json`），不得把事件文本、数值表写死在逻辑代码里。以后要能只改 JSON 就新增事件 |
| 调试模式 | 提供调试面板（如 URL 参数 `?debug=1` 或快捷键）：快进 N 年、增减资源、触发指定事件、直接占领/丢失地块、杀死角色、显示当前随机种子 |
| 文档 | 根目录 `README.md`：运行方法、目录结构、如何新增事件（附 JSON 字段说明）、调试模式用法 |
| 兼容 | 桌面端 Chrome / Edge 最新版即可，**不需要适配手机** |

建议目录结构（可调整）：
```
src/
  core/        # 时间推进、随机数、存档
  systems/     # 角色、修炼、事件、经济、地图、外交、战斗、AI势力
  data/        # events.json, personalities.json, industries.json, realms.json, tiles.json, items.json ...
  ui/          # 界面组件
README.md
```

## 3. 时间模型

- 游戏以**年**为基本单位推进（可细分为春/秋两个阶段，自定）。
- 每年开始，玩家做一次**家族方向决策**：选择产业项目、扩张目标、外交/贸易定价、是否宣战等。
- 年内由系统推进：角色自主修炼/行动、产业经营、AI 势力发展、事件按条件触发。
- **事件驱动的抉择**：需要玩家选择的事件弹窗打断推进，玩家选完再继续。
- 提供"下一年"按钮；可选"自动推进到下一个需要抉择的事件"。
- 角色会**年龄增长**，有寿元上限（境界越高寿元越长），会因寿尽、战斗、天劫、事件死亡。

## 4. 角色系统

### 4.1 属性
每个角色至少包含：
- 基本：姓名、性别、年龄、寿元、所属势力、是否主脉、父母/配偶/子女关系。
- 能力：**天赋**（影响修炼速度、学功法速度）、**机缘**（影响奇遇和事件出现好结果的概率）、悟性/根骨（可选）、战力、经营、交际等（数量自定，需服务于事件和产业判定）。
- 境界与修为、功法/技能。
- **忠诚/对家族的看法**（受婚事、事件影响，过低可能叛变）。
- **善恶倾向**（参与正魔判定，见第 7 节）。

### 4.2 性格（玩家选择，之后会变化）
- 角色出生或入门时，**由玩家选定性格**（如冲动、稳重、怯懦、狠辣、仁厚、贪婪、孤傲……，数据放 `personalities.json`，Demo 至少 8 种）。
- 性格会影响：**哪些选项可选**（例如冲动的人选不了某些稳妥选项）、**选项成功率**、角色自主行动倾向、产业成功率。
- **性格会演变**：重大经历和玩家的选择会让性格慢慢改变（例：怯懦的人经历灭门之仇后变得狠辣）。性格变化要写进日志。

### 4.3 培养方向（玩家选择）
- 玩家为角色选择培养方向（如剑修、体修、丹道、器道、经商、阵法等，数据驱动），影响修炼侧重、技能、适合的产业和岗位。

### 4.4 角色面板
- 每个角色都有可点开的**角色面板**：属性、境界、性格、培养方向、关系、忠诚、**当前想法**（如"李长青觉得自己根基不稳，决定闭关三年"）、个人日志。
- 想法由角色状态生成（瓶颈、仇恨、情缘、资源匮乏等），并对应其接下来的自主行动。

### 4.5 关注与视角
- 玩家可将若干角色设为**重点关注**，被关注角色的个人日志在主界面侧边直接可见。
- 提供**全家族视图**（族谱/成员列表，含主脉、旁支标识）。
- 主角死亡后，家族由继承人延续（默认主脉子嗣，或让玩家在候选人中选），游戏继续。

## 5. 修炼系统

- 境界（`realms.json`）：**练气 → 筑基 → 金丹 → 元婴 → 化神**，每个大境界分**前期 / 中期 / 后期**。
- 修为积累速度受：天赋、功法、培养方向、**资源投入**（资源越多修炼越快）、闭关等影响。
- 大境界突破有**瓶颈**：需要满足条件（修为满、资源/丹药、机缘），有失败概率，失败有后果（受伤、修为倒退等）。
- **高境界突破引来天劫事件**（如金丹及以上），天劫是一个需要抉择/可用道具干预的事件，可能身死。
- 境界决定寿元上限和战斗强度。

## 6. 事件系统（核心内容）

### 6.1 模板 + 变量
- 事件以模板形式写在 JSON 中，文本中用变量占位，运行时从当前世界实时取值。例：
  `"{仇家}带着{人数}名{境界}修士找上门，要为{旧怨}讨说法"`
- 变量可包括：角色、势力、地点/地块、境界、关系、物品、资源数量、旧事件记录等。

### 6.2 触发条件（按逻辑）
- 每个事件有前提条件，例如"有仇人且仇人比你强""角色处于瓶颈期""家族有适婚成员""某地块与魔修相邻"。事件要从世界状态里"长出来"，不是乱弹。
- **属性带来波动**：天赋高的人学功法、突破更快；机缘高的人更容易触发好结果。
- **少量不讲逻辑的意外事件**：低概率触发、无前提或前提很宽，用来打乱局面，同样可以影响因果。

### 6.3 按人分类
- 每个角色有自己的事件线，分类至少包括：**修炼、奇遇、情缘、天劫**。
- 势力层面另有：家族、商业、宗门、战争、魔修、世仇等类别。
- **宗门之争和战斗类事件一旦开始，持续到分出结果**（多阶段事件链 / 持续状态），不能中途凭空消失。

### 6.4 节奏控制
- 同一事件有**冷却时间**，避免短时间重复。
- 可按游戏阶段、类别权重抽取。

### 6.5 结果与因果
- **立刻可见的结果**：选完后马上显示变化（如"修为 +20""与青云宗关系恶化""获得功法《太虚剑诀》""性格：怯懦 → 隐忍"）。
- **长期因果回响**：选择可写入"因果记录"（flag/记忆），在几年甚至几代后触发后续事件。例：当年放走的仇人之子，五十年后带人来报仇。后续事件文本要能引用当年的事。

### 6.6 数量要求
- Demo 提供 **30–50 个事件模板**，覆盖上述全部类别；其中**商业事件要丰富、写得好**（见第 10 节），至少包含若干条因果回响链（≥3 条）、若干持续型事件（宗门之争、战争）、若干无逻辑意外事件。
- 事件 JSON 字段建议：`id, category, title, text, conditions, weight, cooldown, choices[{text, requirements(性格/属性), successRate公式, effects, failEffects, setFlags}], followUps`。

## 7. 世仇、魔修与正魔声望

### 7.1 开局世仇
- 每局开局**随机生成一个世仇家族/势力**（有自己的实力、地盘、发展），与玩家家族有旧怨。
- 世仇会在合适时机（如玩家虚弱、世仇变强）**随时找上门报仇**，给玩家危机感。
- 玩家可选择：躲避、结盟/和解、先下手灭掉它等。
- 后续游戏中，被灭势力逃走的幸存者等也可能成为**新的世仇**。

### 7.2 魔修
- **每个区域都有魔修**，行为**不按逻辑出牌**（随机袭击、劫掠、掳人、扰乱商队、抢秘境），专门制造变数。

### 7.3 声望与正魔判定
- 家族有**正道声望**/善恶值。无故攻打正道、事件中做坏事会累积恶名。
- 坏事做多了达到阈值，**正道将玩家家族定性为魔修**：正道势力态度变差（关系下降、贸易减少、可能联合讨伐），同时可能与魔修关系改善。这一状态要在界面上明确显示，并写入世界日志。

---

## 8. 婚育与传承

- **结婚必须由玩家选择**。前期家族小，每个族人的婚事都弹抉择；**家族壮大后只有主脉人物弹抉择**，旁支自动处理（自动结果写入日志）。
- 角色到适婚年龄主动触发婚事事件，三条路：
  1. **找门当户对的亲家**；
  2. **跟自己喜欢的人在一起**；
  3. **服从家族联姻安排**（与其他势力联姻，可带来外交收益）。
- 不同选择影响该角色**对家族的看法/忠诚**（例：被逼联姻的人心生怨气，日后可能埋下**叛变**伏笔，作为因果回响）。
- 婚后可生子，子女继承部分资质；子女出生/入门时由玩家选性格（见 4.2）。
- 联姻也是"不打而取"的途径之一（见第 12 节）。

## 9. 天道道具（Demo 仅占位）

- 用户会在玩过 Demo 后再设计正式道具。Demo 只做 3 个占位道具，并保证机制可扩展（数据驱动）：
  1. **更换人手**：改变某角色的岗位分配（这是人手调整的**唯一**途径）；
  2. **救命**：让一个即将死亡的角色存活；
  3. **改命**：改变一次事件结果（如把失败改为成功）。
- 道具需有限制：**稀有**（数量少，靠事件/奇遇获得）、有**代价**（如消耗资源/天道之力）或**冷却**。
- 使用时要有**仪式感反馈**（特殊提示文本，如"天降异象，雷劫提前散去"）并写入日志。

## 10. 经济与商业

### 10.1 资源
- **灵石**（通用货币）+ **灵草、矿材、妖兽材料**。
- **不同地块产出不同资源**：山地产矿材、水边产灵草、灵兽领地产妖兽材料等。
- 资源用途：修炼（资源越多修炼越快）、突破、产业、**打仗消耗资源**、贸易。

### 10.2 产业
- 玩家只**选择做什么产业项目**（如坊市、炼丹房、炼器坊、灵田等，`industries.json`），**由角色自己去经营**。
- 产业成败与经营者的**能力和性格**相关：能力和性格对口，成功率高。
- 产业会触发事件，包括**恶性事件**（亏损、事故、被劫、经营者贪污等）。

### 10.3 贸易
- **关系越好的势力越常来贸易**，敌对势力不来甚至劫掠。
- **玩家可设定交易价格**（高于/等于/低于市场价）：价高利润高但成交少、伤关系；价低成交多、涨关系。
- 结盟可增加贸易往来。

### 10.4 恶性事件
- **被劫、丢货、手下叛变**等按概率触发，概率受魔修、关系、忠诚、性格等影响。

### 10.5 人手分工
- 族人和弟子的岗位（修炼、经营、贸易、驻守/打仗等）由系统**自动分配**（按能力/性格/培养方向匹配）。
- **玩家不能直接更换**，只有使用天道道具"更换人手"才能改。

### 10.6 商业事件（重点）
- 必须有，且要做得丰富：如拍卖会出现稀世宝物、商队被魔修劫走、丹药行情大涨/暴跌、对手压价抢生意、伙计卷款潜逃、大宗订单、假货风波等，带有选择和因果。Demo 至少 8 个商业事件。

## 11. 世界地图

- **一块大陆**，划分为 **8–12 个区域**，每个区域由若干**地块**组成（建议网格/六边形格，或区域节点图）。
- 地形/类型：**山、水、平原、秘境、灵兽领地**、主城等，不同类型产出不同资源。
- 主角从**地图角落出生**并建立据点（主城）。
- 大陆上已有**其他几个宗门和家族**，各自占据一定地块。
- **预留空地块**：可让 AI 新势力在游戏中崛起建立。
- **AI 势力也会发展**：扩张、修炼、经营、结仇、结盟、互相攻伐。
- **扩张规则**：只能占领**与主城相连**的己方地盘相邻的空地块（实控地盘相连）。
- **秘境、灵兽领地要打赢战斗才能占领**。
- 地图占满后，各方通过战斗或结盟继续争夺。
- 地图以简单图形呈现即可：地块颜色区分势力，图标/文字标地形，点击地块可查看信息（归属、地形、产出、防御）。

## 12. 占领与势力兴亡

### 12.1 宣战—攻打—占领
1. **宣战**：只能攻打与己方地盘**相邻**的地块。宣战影响声望：打世仇、魔修无人指责；无故攻打正道宗门会被骂，恶名累积（见 7.3）。
2. **攻打**：每块地有**防御值**（受护山大阵、驻守修士、境界影响）。攻方派队伍进入战斗，**每打赢一次削弱防御**，**防御归零才能占领**。**主城最难打**，通常要打多次。
3. **占领后**：地块须与己方主城**相连才稳固**；被切断的**孤立地块会慢慢失守**。守方幸存者可**投降、归顺、逃走**；逃走的人可能成为**新的世仇**（因果回响）。

### 12.2 灭亡与流亡
- 一个势力**主城被占且地块全部丢失**即灭亡。
- AI 势力若还有族人活着逃出，可作为**流亡势力**在空地或秘境重新起家。

### 12.3 不打而取
- **结盟、联姻、附庸、吞并**：通过外交把对方纳入势力。
- **声望震慑**：弱小势力可能因玩家声望/实力**主动归附**。

## 13. 战斗系统（Demo 简化版）

- 战斗**要有玩家参与**，同时提供**一键自动战斗**按钮跳过。
- 战场：小型**战线/格子**战场（如 3 条战线 × 若干格，或小网格）。
- 双方各若干**小队**，每队有将领（角色）+ 兵力（弟子/修士）。
- **回合制但带时间轴**：每回合双方**同时行动**，按时间轴/速度结算。
- 玩家指令：每支小队**移动、进攻、撤退**；**主将的技能由玩家亲手释放**；**非主将（或玩家未操作的将领）自动释放技能**。
- 战斗**消耗资源**（灵石/丹药等）；伤亡、将领死亡会影响家族，结果写入日志。
- 战斗结果作用于地块防御（见 12.1）、秘境/灵兽领地占领、世仇/魔修袭击防守等。
- 战斗强度与境界、功法、兵力、地形挂钩。
- 后续正式版才会升级为类似《全面战争》的实时战斗，**Demo 不做实时**。

---

## 14. 日志系统

- **世界时间日志**：所有重要事件（宣战、灭族、结盟、天劫、境界突破、世仇来袭、被定性为魔修等）按年份记录，可滚动查看。
- **个人日志**：每个角色有个人日志；**重点关注**的人物个人日志在主界面直接可见。
- 自动处理的事件（旁支婚事、AI 势力动作）也要进入日志。

---

## 15. 胜负条件

- **胜利**：占领大陆上的**全部地块**。
- **失败**：玩家**地块全部丢失**，或家族**人全部死光**。
- 只要还有家族成员活着且仍有地块，游戏继续（主角死后由继承人接续）。
- 胜利/失败要有结算画面（显示年份、家族代数、关键事件回顾等）。

## 16. 建议开发里程碑（按顺序增量交付）
