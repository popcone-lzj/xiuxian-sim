# 《修仙家族模拟器》Demo 验收规则

> 审核方依据本规则验收开发方（Codex）提交的 Demo。规则对应《开发说明.md》，只验 Demo 范围内的内容。
> 每条为**通过 / 不通过**判定，并写明验证方法：【玩】= 实际游玩操作；【调】= 使用调试模式；【查】= 检查代码/数据文件。

---

## 0. 问题等级与通过标准

| 等级 | 含义 | 示例 |
|---|---|---|
| **阻断（Blocker）** | 无法运行、崩溃、核心系统缺失或完全不可用、存档损坏、出现已明确删除的内容（如飞升） | `npm run dev` 启动失败；推进 20 年必崩；没有战斗系统 |
| **严重（Major）** | 系统存在但规则与说明不符，或明显影响玩法体验 | 能占领不相连的地块；人手可直接手动换；婚事不让玩家选 |
| **轻微（Minor）** | 文本错别字、界面排版、数值不平衡但可玩、小显示问题 | 日志时间格式不统一；按钮文字被截断 |

- **通过标准：阻断问题为 0。** 严重问题原则上也要修复，审核方可视情况允许个别严重问题留到下一轮；轻微问题记录在案即可。
- 下文每条标注默认等级：🔴 阻断 / 🟠 严重 / 🟡 轻微。

## 15. 模拟通关清单（整体试玩）

用固定种子开新局，主要用正常游玩，必要时用调试模式，逐项打勾：

- [ ] 连续游玩 **50+ 游戏年**无崩溃、无卡死（🔴）
- [ ] 世仇至少来袭 1 次（🟠）
- [ ] 魔修至少在 2 个区域有动作（🟠）
- [ ] 完成至少 1 次婚事抉择并生出后代（🔴）
- [ ] 为新生子女选择性格（🟠）
- [ ] 至少 1 名角色性格发生演变（🟠）
- [ ] 至少 1 名角色突破大境界，至少 1 次天劫（🟠）
- [ ] 至少 1 名角色死亡，继承正常（🔴）
- [ ] 至少 1 个因果回响事件出现（🟠）
- [ ] 建立 1 个产业并出现 1 次商业事件（🟠）
- [ ] 完成 1 次贸易并调整过价格（🟠）
- [ ] 占领 1 块空地、1 块秘境或灵兽领地、1 块敌方地块（🔴）
- [ ] 亲手指挥 1 场战斗并放主将技能，另用自动战斗打 1 场（🔴）
- [ ] 通过"不打而取"获得 1 块地或 1 个附庸（🟠）
- [ ] 存档→读档后继续游玩无异常（🔴）
- [ ] 胜利、失败（地块全失）、失败（人死光）三种结局均可达成（🔴）

## 17. 验收流程

1. **提交**：Codex 完成一个里程碑（或整体 Demo）后提交代码，并附说明：完成了哪些内容、已知问题、本轮测试用的随机种子。
2. **验收**：审核方按本规则对应章节逐条检查，执行"模拟通关清单"。
3. **反馈**：审核方返回**编号问题清单**，每条包含：编号、对应规则号、等级、复现步骤、期望结果、实际结果。
4. **修复**：Codex 按清单逐条修复，回复中按编号说明修复方式。
5. **复验**：审核方复验已修复项，并回归检查存档、运行、通关清单；如有新问题继续编号。
6. **结束**：**阻断问题为 0** 即判定通过，提交给用户试玩；剩余严重/轻微问题列入下一轮待办。
